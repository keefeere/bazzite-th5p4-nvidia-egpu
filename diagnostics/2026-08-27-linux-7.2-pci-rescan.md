# Linux 7.2 PCI rescan compatibility note

## Regression signature

The previously validated Bazzite deployment used Linux
`6.17.7-ba29.fc43.x86_64`. After updating to Linux
`7.2.0-ogc6.1.fc44.x86_64`, the enclosure, RTX endpoint and matching NVIDIA
610.57.04 module were all present, but `egpu-nvidia-boot.service` failed before
loading NVIDIA.

The strict local verifier reported:

```text
LOCAL TH5P4 RESERVE VERIFY FAILED: dock-port MMIO reserve is smaller than the profile target
```

Before the controlled remove/rescan, the scripts programmed the exact validated
TH5P4 downstream-port reserves:

```text
I/O        0xc000-0xefff       12 KiB
MMIO       0xc9000000-0xd0ffffff 128 MiB
MMIO_PREF  0x6402000000-0x6441ffffff 1 GiB
```

On 7.2 the PCI core retained the local bus ranges but normalized each empty
downstream bridge to its default 2 MiB MMIO and 2 MiB prefetchable window. The
verifier therefore failed correctly and kept NVIDIA blocked. The proprietary
driver itself was not the cause: package version, module vermagic and the
running kernel matched.

## Rejected realloc attempt

`pci=realloc=on` was tested as a guarded first compatibility attempt and made
the topology worse before the early service ran. Linux globally repacked the
enclosure upstream bridge from buses `02-60` to `02-06`, assigned one bus and
2 MiB windows to each empty port, and changed the RTX bridge's prefetchable
window. The unchanged profile preflight rejected that boot:

```text
LOCAL RESERVE PREFLIGHT FAILED: eGPU branch MMIO_PREF window differs from the configured profile
```

The active AMD session remained usable because NVIDIA stayed blocked. This
result proves that `pci=realloc=on` is not a local TH5P4 compatibility fix and
must be removed from any deployment previously staged by this project.

## Version-gated hot-plug sizing experiment

The preceding 7.2 boot *without* realloc is more informative: the clean
profile preflight passed and Linux imported every locally programmed bus range
exactly (`02-60`, `04-22`, `23-41`, `42-60`). Only the empty bridge memory
windows were recomputed. Kernel 7.2's `pbus_size_mem()` now obtains that
optional capacity from the standard `hpmmiosize` and `hpmmioprefsize` inputs
instead of retaining the pre-programmed old size.

The guarded replacement policy is therefore:

- `< 7.2`: retain the already validated flow exactly as before;
- `>= 7.2`: require the exact
  `pci=hpmmiosize=32M,hpmmioprefsize=32M` argument, then perform the same local
  writes, remove/rescan and complete capacity/containment checks;
- reject `pci=realloc=on`, `pci=assign-busses`, `hpbussize` and any mismatched
  hot-plug sizing values;
- require at least the already measured 32 MiB MMIO and 32 MiB MMIO_PREF on
  all three empty TH5P4 hot-plug ports; retain the older 128 MiB/1 GiB port-1
  expectation on legacy kernels;
- every verification failure remains fail-closed with NVIDIA unloaded.

The root port has 319 MiB free non-prefetchable MMIO after the clean RTX
window. Three 32 MiB downstream reserves plus the RTX branch fit without
global bridge reassignment, while 32 MiB is the previously recorded minimum
for the nested HP bridge tree. This remains an experiment until a real reboot,
NVIDIA initialization and complete HP Dock verification pass on the target
topology.

## Secondary udev symptom

The internal remove/rescan emits a PCI audio add event. When the early reserve
failed, the quarantine service previously interpreted that event as a physical
cable reconnect. A dedicated `/run/egpu-local-reserve-failed` marker now keeps
that state distinct in the service log and tray UI.
