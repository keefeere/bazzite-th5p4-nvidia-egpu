# Linux 7.2 PCI rescan compatibility note

## Regression signature

The previously validated Bazzite deployment used Linux
`6.17.7-ba29.fc43.x86_64`. After updating to Linux
`7.2.0-ogc6.1.fc44.x86_64`, the enclosure, RTX endpoint and matching NVIDIA
610.57.04 module were all present, but `egpu-nvidia-boot.service` failed before
loading NVIDIA.

The strict local verifier reported:

```text
LOCAL TH5P4 RESERVE VERIFY FAILED: dock-port MMIO reserve is smaller than the profile target
```

Before the controlled remove/rescan, the scripts programmed the exact validated
TH5P4 downstream-port reserves:

```text
I/O        0xc000-0xefff       12 KiB
MMIO       0xc9000000-0xd0ffffff 128 MiB
MMIO_PREF  0x6402000000-0x6441ffffff 1 GiB
```

On 7.2 the PCI core retained the local bus ranges but normalized each empty
downstream bridge to its default 2 MiB MMIO and 2 MiB prefetchable window. The
verifier therefore failed correctly and kept NVIDIA blocked. The proprietary
driver itself was not the cause: package version, module vermagic and the
running kernel matched.

## Compatibility boundary

Linux documents `pci=realloc=on` as enabling reassignment of PCI bridge
resources when firmware allocations are too small. The guarded compatibility
policy is therefore:

- `< 7.2`: retain the already validated flow exactly as before;
- `>= 7.2`: require the exact `pci=realloc=on` argument, then perform the same
  TH5P4-only writes, remove/rescan and complete capacity/containment checks;
- every verification failure remains fail-closed with NVIDIA unloaded;
- never use `pci=assign-busses` or global hot-plug size arguments.

The 7.2 path is not considered validated merely because the kernel argument is
present. It still has to pass the complete live local-reserve verifier and a
real reboot test on the target topology.

## Secondary udev symptom

The internal remove/rescan emits a PCI audio add event. When the early reserve
failed, the quarantine service previously interpreted that event as a physical
cable reconnect. A dedicated `/run/egpu-local-reserve-failed` marker now keeps
that state distinct in the service log and tray UI.
